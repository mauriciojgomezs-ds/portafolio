## Ejecutar un proyecto

1. Abre `Analisis/<tema>/<proyecto>` y sigue su README para recuperar las fuentes locales, crear el entorno e instalar `requirements.txt`.
2. Selecciona ese Python como kernel y ejecuta 00. Si instala dependencias, reinicia el kernel y repite la comprobación.
3. Guarda y cierra 01–05 antes de ejecutar las tres celdas de 06. El maestro recorre solo las cinco etapas de su proyecto y se detiene ante errores.
4. Revisa el informe integral, el resumen de ejecución y las alertas. También puedes ejecutar etapas individualmente respetando sus dependencias.

| Etapa | Propósito |
| --- | --- |
| 00 | Entorno y comprobaciones previas; preparación de la fuente cuando corresponde |
| 01 | Preparación de datos y particiones cuando corresponden |
| 02 | Análisis exploratorio y comentarios calculados |
| 03 | Baseline o referencia descriptiva |
| 04 | Modelado, selección o construcción de indicadores |
| 05 | Evaluación y conclusiones con límites explícitos |
| 06 | Ejecución secuencial de 01–05 |

Los nombres exactos de 01–05 pueden variar por proyecto. En RetailKPIAnalysis, 04 construye indicadores y 05 verifica su reconciliación. Las métricas de clustering y recomendación por contenido son descriptivas; cada guía explica qué permite afirmar su evaluación.

## Resultados y reproducción

El punto de entrada es `reports/informe_final/informe_final.md`, dentro del proyecto. Los detalles se guardan en carpetas de etapa y `reports/ejecucion/resumen.json` registra el avance del maestro. Para reunir evidencia existente sin recalcular modelos, utiliza `python scripts/generate_report.py` desde el proyecto.

Los informes se actualizan automáticamente. Las cifras de un README o una revisión histórica pueden corresponder a una ejecución anterior; consulta la fecha, configuración y fuentes del informe vigente. Un maestro fallido puede dejar resultados anteriores, que el informe identifica. Una tabla sin avisos no acredita calidad del modelo.

## Autonomía y alcance

Cada carpeta contiene su paquete en `src`, requisitos, scripts, tests, configuración cuando corresponde, datos y documentación. Se puede copiar o renombrar con sus fuentes locales. `Analisis`, los otros temas y `back` no aportan funciones necesarias para ejecutarla. Para otra máquina, crea un entorno nuevo siguiendo el README local.

Los análisis se distinguen por su objetivo: existen evaluaciones predictivas, diagnósticos descriptivos y escenarios sujetos a supuestos. Por ejemplo, AI4I es sintético; los recomendadores de contenido no miden satisfacción personal; la dotación de call center no acredita un SLA real. Las limitaciones concretas están en cada metodología e informe.

Las aplicaciones de dashboards están en [BusinessIntelligence](../BusinessIntelligence/README.md). Los asistentes y MVP están en [IAG](../IAG/README.md), incluido [Knowledge Base MVP](../IAG/knowledge_base_mvp/README.md), cuyo flujo de consola tiene documentación propia.

Consulta la [guía temática](../docs/proyectos_tematicos.md), el [índice de informes](../docs/informes_integrales.md), la [organización general](../docs/organizacion_portafolio.md) y la [verificación del traslado](../docs/verificacion_organizacion_analisis.json). Esta última comprobó rutas, sintaxis y generación de informes de 133 notebooks; no repitió entrenamiento ni validó una instalación limpia de todos los proyectos.

La [ampliación de análisis](../docs/ampliacion_analisis.md) incorpora 21 notebooks ejecutados y comprobados por separado. En esa ampliación se llegó a 154 notebooks en 22 proyectos; el registro del traslado anterior conserva su alcance histórico.

La [ampliación del 8 de octubre](../docs/ampliacion_analisis_oct08.md) añade grafos y supervivencia y complementa turnos y los cuatro proyectos churn. Total actual: **24 proyectos, 13 temas y 168 notebooks**.
